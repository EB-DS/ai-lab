# Production LLM Serving & API Engineering

## Overview

This project explores how to turn a locally hosted large language model into a production-style API service.

The system is being built incrementally:

1. FastAPI service foundation
2. Health and model discovery endpoints
3. OpenAI-style chat completion endpoint
4. Backend abstraction
5. Configuration-driven backend selection
6. Automated API tests
7. Transformers-based local LLM backend
8. GPU inference
9. Streaming responses
10. Concurrency and performance testing

## Real GPU-Backed LLM Serving

The API has now progressed from the mock backend to real local LLM inference.

The Transformers backend was successfully tested with:

- Model: `Qwen/Qwen2.5-7B-Instruct`
- Framework: Hugging Face Transformers
- PyTorch: 2.8.0 with CUDA 12.8
- GPU: NVIDIA RTX PRO 4500 Blackwell Server Edition
- GPU memory: approximately 31.37 GB

The model was loaded on the GPU and served through the existing FastAPI application.

A request was successfully sent to:

`POST /v1/chat/completions`

using the prompt:

> Explain what an LLM API is in simple terms.

The API returned a real response generated by Qwen2.5-7B-Instruct through the Transformers backend.

Observed generation latency for this first test was approximately **2.51 seconds**.

The completed serving path was:

This is an important Project 2 milestone because the same API contract originally developed and tested with the mock backend now works with a real GPU-hosted language model.

## Token Usage Accounting

The API now returns real token usage from the active LLM backend in the OpenAI-style `usage` field.

For the Transformers backend:

- `prompt_tokens`: number of input tokens
- `completion_tokens`: number of generated tokens
- `total_tokens`: prompt tokens + completion tokens

A real GPU-backed request using `Qwen/Qwen2.5-7B-Instruct` produced:

- Prompt tokens: 41
- Completion tokens: 96
- Total tokens: 137
- Generation latency: approximately 2.49 seconds

The mock backend intentionally returns `null` token counts because it does not run a tokenizer or language model.

This milestone provides usage metadata needed for observability, benchmarking, capacity planning, and future usage-based accounting.
